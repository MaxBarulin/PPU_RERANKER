# План: подключение к базе данных ППУ

Цель: брать реестр ППУ прямо из SQL-базы, а не загружать Excel. Сначала
нужно получить у ИТ сведения и доступы, перечисленные ниже. Готовый текст
письма - в конце.

## Что нужно узнать

### 1. Что за база

Тип СУБД и версия: MS SQL Server, PostgreSQL, Oracle или другая. От этого
зависит, чем подключаться.

### 2. Куда подключаться

- адрес сервера (имя или IP) и порт; для MS SQL обычно 1433;
- для MS SQL - имя экземпляра, если он не основной (вида `СЕРВЕР\ЭКЗЕМПЛЯР`);
- имя базы данных.

### 3. Учётная запись

- отдельный логин **только на чтение**, с правом SELECT только на нужную таблицу;
- лучше логин самой СУБД (SQL login) с паролем. Вход через доменную учётку
  Windows с Linux-сервера настраивать сильно сложнее.

### 4. Сетевой доступ

С `srv-ai` должно пускать к серверу БД по нужному порту, то есть нужно открыть
доступ через сетевой экран. Без этого остальное не поможет.

### 5. Откуда брать данные

Лучше всего попросить сделать **отдельное представление (view)** с нужными
полями. Тогда сервис не зависит от внутреннего устройства их базы: если они
что-то переделают, view останется прежним.

| Поле | Обязательно? |
|---|---|
| уникальный ID записи (не меняется со временем) | да |
| регистрационный номер | да |
| наименование | да |
| до улучшения | да |
| после улучшения | да |
| предложения | да |
| результат | желательно |
| статус | желательно |
| экономический эффект | желательно |
| даты: подачи, регистрации, рассмотрения, реализации, ЭЭ | желательно |
| **дата последнего изменения записи** | очень желательно |

Дата изменения позволит при обновлении базы забирать только новые и изменённые
записи, а не всю таблицу.

### 6. Технические мелочи

- **Кодировка русского текста:** `nvarchar` или `varchar` с кодировкой cp1251.
  Иначе вместо букв могут быть «кракозябры».
- **Шифрование соединения:** нужно ли оно, и если да, доверенный ли у сервера
  сертификат.
- **Можно ли поставить на `srv-ai` драйвер СУБД** (для MS SQL это «ODBC Driver
  for SQL Server»). Если нельзя, есть драйверы, которые ставятся без прав
  администратора. Просто нужно знать заранее.

### 7. Вложения (необязательно)

У части старых ППУ в описании «См.вложение». Где хранятся сами файлы вложений
и можно ли получить из них текст? Тогда сервис стал бы точнее на старых записях.

### 8. Как часто можно читать

Не будет ли проблем, если сервис раз в день (или по кнопке) читает весь реестр:
это около 11 тыс. строк. И есть ли тестовая копия базы, чтобы сначала
попробовать на ней.

## Готовый текст для ИТ

> Добрый день! Для внутреннего сервиса проверки ППУ на повторы (работает на
> сервере srv-ai) нужен доступ на чтение к реестру ППУ в базе данных. Прошу
> сообщить и, по возможности, предоставить:
>
> 1. Тип и версию СУБД, адрес сервера, порт, имя экземпляра (если есть) и имя базы.
> 2. Учётную запись SQL только на чтение (SELECT) к данным реестра ППУ.
> 3. Сетевой доступ с srv-ai к серверу БД по этому порту.
> 4. Если возможно, отдельное представление (view) с полями: уникальный ID,
>    рег. №, наименование, «до улучшения», «после улучшения», «предложения»,
>    результат, статус, экономический эффект, даты подачи / регистрации /
>    рассмотрения / реализации / ЭЭ и дата последнего изменения записи.
> 5. Кодировку текстовых полей и требования к шифрованию соединения.
> 6. Можно ли установить на srv-ai драйвер для подключения к СУБД.
> 7. Где хранятся вложения к ППУ и можно ли получить их текст (необязательно).
> 8. Есть ли тестовая копия базы, и устраивает ли вас чтение реестра
>    (около 11 тыс. строк) раз в день.
>
> Доступ нужен только на чтение, данные остаются на заводском сервере.

## Что будет дальше

Когда ИТ пришлют ответы, на странице `/admin` появится кнопка «Обновить из
базы» рядом с загрузкой Excel. Пароль от базы будет храниться в `.env` на
сервере, а не в коде и не в git. Сборка индекса уже устроена так, что
источник данных меняется одной функцией, остальное останется как есть.
