# Запуск на Linux-сервере

Модели уже работают на сервере, поэтому запускаем только веб. База (индекс)
загружается и пересобирается **из браузера**, на странице `/admin`, без
командной строки.

Пример ниже — для сервера, где:

| Что | Где |
|---|---|
| чужой веб-интерфейс к LLM | порт 8000 — **не трогаем** |
| сервер эмбеддингов bge-m3 | `127.0.0.1:8001` |
| LLM (судья) | `127.0.0.1:8004` |
| **наш веб** | порт **8010** (любой свободный) |

## Первый раз

```bash
cd ~
git clone https://github.com/MaxBarulin/PPU_RERANKER.git   # если ещё нет
cd ~/PPU_RERANKER
scripts/linux/start.sh       # создаст venv и .env, поставит зависимости
scripts/linux/stop.sh
nano .env
```

В `.env` поправить:

```
EMB_BASE_URL=http://127.0.0.1:8001/v1
EMB_MODEL=bge-m3
LLM_BASE_URL=http://127.0.0.1:8004/v1
LLM_MODEL=<имя из: curl http://127.0.0.1:8004/v1/models>
PPU_PORT=8010
PPU_ADMIN_TOKEN=<пароль на обновление базы, можно оставить пустым>
```

Без LLM можно работать: оставьте `LLM_BASE_URL=` пустым, тогда кнопки
«Уточнить у LLM» не будет.

## Запуск и остановка

```bash
cd ~/PPU_RERANKER
scripts/linux/start.sh
```

Скрипт проверит, что модели отвечают, запустит веб в фоне и напишет адреса:

```
Модели из .env:
  эмбеддинги: OK  (http://127.0.0.1:8001/v1)
  LLM-судья : OK  (http://127.0.0.1:8004/v1)

Работает (PID 12345):
  проверка ППУ:     http://10.x.x.x:8010
  обновление базы:  http://10.x.x.x:8010/admin
```

Веб продолжает работать и после закрытия терминала или выхода из SSH.

| Действие | Команда |
|---|---|
| остановить | `scripts/linux/stop.sh` |
| перезапустить | `scripts/linux/stop.sh && scripts/linux/start.sh` |
| смотреть лог | `tail -f logs/web.log` (выйти — Ctrl+C, веб продолжит работать) |
| обновить код из git и перезапустить | `scripts/linux/update.sh` |
| переключиться на другую ветку | `scripts/linux/update.sh <ветка>` |

## Обновление базы

1. Открыть `http://<сервер>:8010/admin`.
2. Выбрать файл реестра `.xlsx` и нажать **«Загрузить и пересобрать»**.
3. На странице видно, какой шаг идёт и сколько записей уже посчитано.
   Страницу можно закрыть, сборка продолжится.

Что происходит:

- лист и строка заголовка находятся сами по колонкам «Наименование», «До
  улучшения», «После улучшения», «Предложения»;
- векторы уже посчитанных записей берутся из кэша (`data/emb_cache.sqlite`),
  поэтому повторная загрузка пополненного реестра идёт быстро: считаются только
  новые и изменённые записи;
- пока идёт сборка, проверка ППУ работает по **старой** базе; новая подменяет
  её целиком, только если сборка прошла успешно, и перезапускать веб не нужно;
- если сборка оборвалась (сервер эмбеддингов упал, веб перезапустили),
  нажмите **«Пересобрать из последнего файла»**: уже посчитанное возьмётся
  из кэша;
- после сборки на странице есть «Отчёт о данных»: сколько записей без
  описания, повторяющиеся названия, нераскрытые сокращения.

Старый формат `.xls` не читается. Пересохраните файл в Excel как «Книга Excel (.xlsx)».

То же из командной строки (если удобнее):

```bash
venv/bin/python -m ppu.rebuild "Реестр ППУ.xlsx"
```

Чтобы веб подхватил базу, собранную из командной строки, его нужно перезапустить.

## Автоподъём после падения и перезагрузки

Сам `start.sh` веб не перезапускает: если процесс упал или сервер
перезагрузили, веб остаётся выключенным. Чтобы он поднимался сам, добавьте
проверку раз в 5 минут в `crontab -e`:

```
*/5 * * * * cd ~/PPU_RERANKER && scripts/linux/start.sh >> logs/start.log 2>&1
```

Если веб работает, `start.sh` сразу выходит («Уже запущен»). Если не работает,
запускает его. Так веб поднимется не позже чем через 5 минут и после падения, и после
перезагрузки сервера.

Проверить:

```bash
crontab -l | grep PPU_RERANKER        # строка на месте
systemctl is-active cron              # cron работает: active
scripts/linux/stop.sh                 # «уронить» веб
# подождать до 5 минут
tail -5 logs/start.log                # видно, что start.sh его поднял
curl -s http://127.0.0.1:8010/api/info
```

Если `crontab -e` пишет, что вам запрещено (доменные учётки иногда не пускают
в cron), попросите администратора сервера.

## Частые ошибки

| Сообщение | Что значит |
|---|---|
| `Порт 8010 занят другой программой` | поставьте другой порт в `PPU_PORT` в `.env` |
| `эмбеддинги: НЕ ОТВЕЧАЕТ` | сервер на 8001 не запущен или в `EMB_BASE_URL` неверный адрес; проверьте `curl http://127.0.0.1:8001/v1/models` |
| на /admin: `APIConnectionError` | то же: сборке нужен сервер эмбеддингов |
| `Не найден лист с колонками` | в Excel нет колонок с ожидаемыми заголовками (см. выше) |
| страница не открывается с другого компьютера | порт закрыт сетевым экраном; временно можно через туннель: `ssh -L 8010:127.0.0.1:8010 <логин>@<сервер>` и открыть http://127.0.0.1:8010 |
| судья LLM отвечает ошибкой про `reasoning` | LLM-сервер не понимает параметр; задайте в `.env` `LLM_EXTRA_BODY={"chat_template_kwargs": {"enable_thinking": false}}` |

> Индекс и запросы должны считаться одной и той же моделью эмбеддингов. Если
> на 8001 поменяли модель, загрузите реестр заново. Кэш эмбеддингов привязан
> к `EMB_MODEL`, поэтому при новой модели поменяйте и это имя.
